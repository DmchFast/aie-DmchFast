- **Название проекта:** `Классификация изображений (Intel Image Classification)`
- **Автор:** `Чуваев Дмитрий Сергеевич`
- **Группа:** `ЭФБО-06-24`
- **Контакт:** `chuvaev.d.s@edu.mirea.ru`

- **Краткое описание:**
  `Проект решает задачу классификации изображений из датасета Intel Image Classification. Включает подготовку данных (EDA, преобразования), реализацию baseline и обучение    с переносом обучения на ResNet-18. Есть скрипты для воспроизводимости экспериментов, логирование метрик (MLflow) и минимальный FastAPI-сервис для инференса.
  Модель сохраняется в artifacts/best_model.pth. Итоговая тестовая точность указана в report.md (примерно 0.92–0.94 в эксперименте с fine-tuning).`

---

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - EDA, прототипы моделей, отдельные эксперименты.
- `src/` – основной код проекта:
  - модули для работы с данными;
  - обучение моделей;
  - запуск сервиса/скриптов.
- `data/` – демонстрационные/учебные данные:
  - **только открытые, синтетические или обезличенные данные;**
- `configs/` – конфигурационные файлы:
  - `.yaml`, `.json`, `.env.example` и т.п.
- `tests/` – тесты.
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов.

## 3. Требования и установка

- Python `>= 3.10` (проект проверен на Python 3.12 и 3.14).

Установка:

```bash
# Перейти в папку проекта
cd project

# Создать виртуальное окружение
python -m venv .venv

# Активировать окружение:
# Windows:
.venv\Scripts\activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt
```

---

## 4. Как запустить проект

### 4.1. Запуск проверки установленных библиотек

```bash
python -m test_imports.py             
```

### 4.2. Запуск обучения моделей (если в src/model их нет, либо необходимо изменить параметры)

```bash
cd project

# Активировать виртуальное окружение (Windows)
.venv\Scripts\activate

# Запустить сервер
uvicorn src.app:app --host 127.0.0.1 --port 8000
```

Проверка:

```bash
curl http://127.0.0.1:8000/health
curl -X POST "http://127.0.0.1:8000/predict" -F "file=@C:\\path\\to\\image.jpg"
```


Ключевые эндпоинты:
- `GET /health` — проверка готовности сервиса и загруженной модели.
- `POST /predict` — принимает изображение (multipart/form-data, поле `file`) и возвращает предсказанный класс и вероятности по всем классам.

Тестирование работоспособности:

- Через браузер (Swagger UI): откройте http://127.0.0.1:8000/docs, выберите `POST /predict`, загрузите изображение и выполните запрос — в ответе будет JSON с полем `class` и `probabilities`.

- Через `curl` (терминал): пример запроса к эндпоинту инференса:

```bash
curl -X POST "http://127.0.0.1:8000/predict" -F "file=@C:\path\to\image.jpg"
```

## 8. Ограничения и дальнейшая работа

Текущие ограничения для текущего CV-проекта:

- Валидация проведена на подвыборке датасета; результаты могут отличаться на полном `seg_test`.
- Модель обучалась на ResNet-18 и не проходила масштабный гиперпараметрический тюнинг — возможен прирост качества при подборе LR, scheduler или увеличении числа эпох.
- Для реального продакшена полезно добавить обработку ошибок при некорректных изображениях и ограничение размера загружаемых файлов.

Планы на развитие:

- Подтвердить метрики на полном тестовом наборе и добавить `classification_report`.
- Попробовать простую настройку гиперпараметров (LR, scheduler) и протестировать 1–2 альтернативных backbone.
- Добавить базовую валидацию входа в API (проверка формата/размера изображения) и улучшить логирование ошибок.
